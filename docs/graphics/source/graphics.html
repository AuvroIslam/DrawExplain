How do I get the shortest path from A to E?
Dijkstra's algorithm finds the shortest path from a source node to every other node in a weighted graph with non-negative edge weights. It maintains a set of visited nodes and a priority queue of tentative distances. Initially, the distance to the source is zero and every other distance is infinity. At each iteration, the algorithm selects the unvisited node with the smallest tentative distance, marks it as visited, and relaxes each of its neighbours by checking whether a shorter path exists through the current node. This continues until all nodes have been visited or the destination is reached. In your graph, the path would likely go through the nodes with the lowest weights...

Our solution

A tutor that teaches by drawing on your page

1

See

Computer vision

OCR reads every line and label, OpenCV finds the shapes, SAM sharpens unsure ones. Each thing on the page becomes a numbered region.

2

Plan

Language model

The model plans the lesson by naming regions, not pixels: what to circle, what to write, and when the voice says it.

3

Check

Code

Every drawing is cross-checked against the region. For an algorithm, code runs it on the graph or table read off the page.

4

Teach

Whiteboard + voice

Marker strokes appear on the untouched page in sync with the narration. Ask a follow-up, then take a tap quiz.

The model never draws and never does the arithmetic. Vision and code decide where, and what the numbers are.
